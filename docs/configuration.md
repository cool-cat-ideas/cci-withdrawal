# Choose who can use the withdrawal form

Open **Cool Cat Ideas > CCI Withdrawal Form**.

## Choose the buyer types

- Turn on **Consumer purchases** for ordinary consumer orders.
- Turn on **Non-professional sole trader purchases** if the shop accepts statements from sole traders whose purchase was not professional in nature.
- **Company and professional purchases** shows a contact message. It does not create a merchandise return.

Keep at least one buyer type enabled. Ask your legal adviser which paths and wording fit your store.

## Let guests find an order

When guest access is on, the buyer enters the order reference and the same email address used at checkout. The module does not reveal order details until both values match.

Leave this on when your shop accepts guest orders. If you turn it off, give guests another clear way to contact the store.

## Exclude products only when needed

You can exclude customized products automatically and list other product IDs. Use this only for products that really should be excluded under your store's rules.

## Decide whether to ask for a message

The message can be shown or hidden. When shown, it is always optional and never blocks a statutory withdrawal statement. The form displays a privacy notice instead of requiring a marketing-consent checkbox.

## Choose access points and confirmations

Each placement can be enabled separately:

- footer on every storefront page;
- customer account;
- order history and order details, including a generic link on guest tracking when the theme does not expose an order object;
- order confirmation page;
- a separate transactional access email sent after checkout.

The order-specific URL is signed and only prefills a matching order. Opening it does not submit a statement. PDF confirmation is optional.

## Check the form

Test one signed-in order and one guest order. Also test full and partial requests, a repeated confirmation, an order outside the native return period, a digital item and failed mail delivery. Each statement must remain visible in the inbox even when no native RMA is created.
